# 整合来源与取舍

本项目将企业知识库和多智能体研究助手融合为一个持续对话应用。原目录保持只读，新代码、环境、数据库与运行产物位于 `grounded-research-agent`。

## 融合的中心是聊天会话

单纯把两个入口放在一个菜单里，不会让它们共享对话。新的主入口是 `/chat`：一个会话保存历史、摘要和允许使用的来源，主 Agent 在回答时按需调用 RAG 子 Agent 或研究子 Agent，并将工具结果带回当前对话。

保留知识库项目的一套账户与数据库，避免第二套登录、Token和历史归属。已有研究图作为主 Agent 可用的研究能力，原研究项目的独立账户、SQLite历史和前端不作为第二个应用运行。

## 新增连接

1. **历史到主 Agent。** 会话/轮次/消息模型保存输入和回答，worker读取成功历史及摘要后处理下一轮。失败和取消保留展示记录，但不作为成功对话进入模型上下文。
2. **主 Agent 到子 Agent。** 工具调用由服务端执行，身份和知识库范围由会话授权约束，模型不能凭工具参数指定其他用户。
3. **子 Agent 到证据。** 私有检索和网页研究返回统一 `Evidence`，为回答引用和来源展示提供一致结构。
4. **执行到界面。** PostgreSQL保存轮次与事件，React聊天页通过SSE显示生成和工具进度，重新打开后读取持久消息与活动轮次。

独立知识库聊天与研究接口仍保留，便于回归和学习已有实现；它们不替代新的统一聊天主入口。

## 不迁移旧数据和密钥

不复制旧 `.env`、API Key、JWT密钥、账户密码、数据库目录、上传文件、向量库或运行中任务。新 `.env` 与数据库单独初始化。需要历史导入时应另做有身份映射、来源校验和备份的数据迁移。

## 保留的边界

- 持续对话使用近期消息与有损摘要，不是无限精准记忆，也不是跨所有会话共享的长期记忆。
- 主 Agent 的按需工具调用和研究子 Agent 的固定图是不同执行层次，不能把其中一个的能力泛化到另一个。
- 消息、轮次、结果和事件在数据库中；任务执行仍依赖进程内 worker。重启标记活动任务失败，不恢复中断节点。
- 不继承原研究项目Redis多进程安全、性能数字、旧截图或旧测试数量作为新融合流程的验证结果。
- 引用支持追溯资料，不自动证明每句回答正确。真实模型工具选择、摘要质量和引用质量需独立评估，本轮没有付费联调。
